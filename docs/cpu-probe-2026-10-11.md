# 临时 CPU 单核与多核对照测试

历史实验记录：临时 CPU 测试入口、实现和相关构建开关已经从正式 1.0.6 中移除。下文记录当时的实验版本与命令，不是当前源码的构建说明。

用途：不用启动 Minecraft，即可比较安兔兔包名和原包名两个应用在手机上的前台 CPU 表现。两个版本使用同一份源代码、发行证书及版本 `11.1.2 / 110010201`。不是安兔兔官方跑分，也不代表 HotSpot 或 `:server` 后台进程性能。

## 操作

首页和设置页均有“临时 CPU 测试 · 单核 / 多核”入口。点击“开始测试”，依次测量：

1. 单线程 64 位整数。
2. 单线程 FP64 浮点。
3. 所有可见核心数量的工作线程，64 位整数。
4. 所有可见核心数量的工作线程，FP64 浮点。

每项先预热 1 秒，再测量 8 秒，共约 36 秒。单核项不设置亲和性，由 Android 选择核心；多核项启动专用线程，共用起跑信号和计时截止点。可以随时停止；离开应用或退出页面会停止并清理工作线程，测试期间保持亮屏。

结果显示每项百万轮/秒、线程数、实际耗时和结果校验值，可以复制整份报告。每轮包含四路计算；吞吐量不是 FLOPS，也不是标准跑分。请只比较相同项目跨版本的数值，不比较整数与浮点项目之间的数值。

先测其中一个版本，复制结果，冷却后再测另一版本；保持电量、是否充电、系统性能模式和省电设置一致，轮换顺序重复几次。报告包含电池温度和系统热状态编号，电池温度不是 CPU 核心温度。测试前停止其他服务器和 CPU 密集任务。

## 实现与测试边界

- `cpu_benchmark.c`：小批次原生整数和 double 循环，结果返回 Kotlin 并作为下一批输入，防止无用计算被删除。整数使用定义明确的无符号溢出运算，浮点禁用 fast-math 与 FMA 收缩。
- `CpuBenchmark.kt`：专用工作线程，统一开始、统一截止、按实际完成时间统计吞吐量；计时和停止判断每批一次，避免每个算术操作调用系统时钟。退出时等待线程清理结束，再允许下一项开始。
- 不提高线程优先级、不绑定大核、不更改系统性能模式或省电设置，使系统对应用身份的调度差异能够保留。
- 安兔兔包名：`com.antutu.ABenchMark`；原包名：`com.mcmobile.server`。这次没有增加其他签名证书版本。
- 原包名版以同一证书覆盖更新原应用，保留应用数据；没有卸载原 MC 服务器。其临时版本号也提升到 `110010201`，后续恢复普通低版本发行包时要处理 Android 的版本降级限制。
- 默认普通构建隐藏该入口，仅测试构建启用清单元数据 `mcs.cpuBenchmarkProbe=true`，没有自动跑分或启动服务端。

## 复现构建

```powershell
.\gradlew.bat :app:testDebugUnitTest --tests com.mcmobile.server.core.benchmark.CpuBenchmarkTest :app:assembleRelease -PantutuVersionProbe=true --console=plain
# 保存原包名 APK 后再构建测试版：
.\gradlew.bat :app:assembleRelease -PantutuPackageProbe=true --console=plain
```

APK 和对照校验结果位于 `release-out/cpu-probe-20261011/`。两个版本完成后用该目录的 `compare-apks.ps1` 逐文件比较，包括 DEX、原生库、运行时 assets 和 ART 预编译配置。

## 验证记录

- 三项 JVM 单元测试通过：工作线程真正并发执行，取消能快速终止一个设定为 30 秒的测试并允许重跑，内核异常后没有遗留计算线程。
- 使用相同原生源文件和编译选项构建 ARM64 短验证，在用户手机上执行少量批次：整数/浮点结果确定且随输入种子变化，批次数为 32768；输出 `CPU_KERNEL_SMOKE_PASSED`。这个验证没有运行完整跑分，不作为性能比较结果。
